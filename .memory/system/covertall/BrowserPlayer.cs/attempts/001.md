Analysis:
- BrowserPlayer is a WebAssembly-only internal player. Its OpenAl P/Invokes use
  DllImport("openal32") which is unresolvable on macOS (only the OpenAL.framework
  exists). The RequireOpenAlFact tests therefore skipped and the instance
  methods could not run.
- Fix: registered a NativeLibrary.SetDllImportResolver in the test class static
  constructor mapping "openal32" to /System/Library/Frameworks/OpenAL.framework/OpenAL
  (with libopenal.1.dylib fallback). This is a standard, AOT-safe interop
  resolution API - not reflection and not runtime code generation. The real
  framework works headless (verified: alcOpenDevice/alcCreateContext/
  alcMakeContextCurrent/alGenSources/alGenBuffers all succeed).
- AssetRegistry: the Memory source generator emits a [ModuleInitializer] that
  registers "Alis.Core.Audio.Test" as the active assembly containing
  sample_1..4.wav. Play("sample_1.wav") reads a valid PCM WAV from the active
  pack. For the invalid-WAV path, re-register the active assembly name with a
  pack containing garbage bytes, then restore via the generated
  ResourceAnchor.LoadAsset().
- Updating BrowserPlayerCoverageCompletionTests: 3 tests that asserted
  DllNotFoundException when calling Pause/Resume/Stop on an uninitialized
  player were failing against the freshly-built binaries because the resolver
  makes openal32 resolvable. Their source already tolerated a null exception
  (stale-binary issue on first run); the resolvable library makes them pass.
