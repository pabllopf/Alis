## Analysis

The constructor pins the pixel buffer, calls `sfCursor_createFromPixels`, and
frees the handle in a finally block. Attempts to exercise it with real pixel
data (4x4 RGBA, 1x1) crashed the test host process: SFML 3.0.x macOS
`CursorImpl::loadFromPixels` -> `[NSImage raw imageWithRawData:andSize:]` raises
EXC_BAD_ACCESS on this machine (Apple Silicon). This is a native library
platform defect, not a test defect.

The documented null-pixels contract (`"If pixels is null ... the function will
return false"`) avoids the crashing code path: `sfCursor_createFromPixels(NULL,...)`
returns false early. A null-pixels construction completes normally and leaves
`CPointer` at `IntPtr.Zero`, executing every line of the constructor body
(190-202), including the native call, try/finally and handle.Free().
