## Environment discovery

- Plain `dotnet test` run of the Glfw test project reports the whole
  `Alis.Extension.Graphic.Glfw` module at 0% despite 604 passing tests,
  because the native GLFW coverage tests are gated behind
  `GlfwTestBootstrap.Ready`, which requires running the test assembly as a
  runtime startup hook (`ALIS_GLFW_HOOK=1` + `DOTNET_STARTUP_HOOKS`).
- Executing the startup hook directly fails before it runs: the source
  generated `[ModuleInitializer]` (ResourceAccessorGenerator) embedded in the
  test assembly attempts to bind `Alis.Core.Aspect.Memory` from the hook
  context, producing
  `FileNotFoundException: Alis.Core.Aspect.Memory, Version=1.4.5.0`.
  This is the shared generator infra issue already documented in
  .memory/system/covertall/index.md.
- Workaround validated (no repo/shared changes): a temporary preload hook
  built in /var/folders/.../opencode/glfw-hook2 preloads the aspect
  assemblies from the test bin `lib` directory through
  `AssemblyLoadContext.Default.Resolving`, after which the Glfw bootstrap
  runs successfully and native coverage is recorded.

Coverage command used (with hook env):
```
ALIS_GLFW_HOOK=1 DOTNET_STARTUP_HOOKS=<preload.dll>:<test.dll> \
dotnet test -f net8.0 -c Debug ./1_Presentation/Extension/Graphic/Glfw/test/Alis.Extension.Graphic.Glfw.Test.csproj \
  --collect "XPlat Code Coverage;Format=opencover" --results-directory <dir>
```
