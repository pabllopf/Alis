## Production fixes (rule 27 - actual defects)

1. NativeWindow.OnKey (src/NativeWindow.cs:1322):
   `else if (state.HasFlag(InputState.Release))` was replaced with
   `else if (state == InputState.Release)`.
   `InputState` is a plain byte enum (Release=0, Press=1, Repeat=2), so
   `HasFlag(Release)` with a zero-valued member is always true and the
   repeat state could never reach the KeyRepeat branch; a repeat event was
   reported as Release. GLFW reports exactly one of Release/Press/Repeat per
   event, so equality check preserves the intended behavior and removes the
   wrong Release-on-Repeat dispatch.
   The previously committed test `FireOnKey_RaisesKeyEvents` asserted the
   buggy behavior (released==2, repeated==0); it was updated to the GLFW
   contract (released==1, repeated==1).

2. NativeWindow.Fullscreen(Monitor): the committed overload passed
   width=0, height=0 to SetWindowMonitor; GLFW rejects it with
   "InvalidValue: Invalid window size 0x0" (recorded by the diagnostic
   observability added in attempt 001). A fix that resolves the monitor
   video mode before attach was implemented and validated, but the real
   display-mode transition on this host segfaults GLFW
   (DiagnosticReports dotnet-2026-09-12-191525.ips, crash inside
   glfwGetVideoMode while switching resolution). Because the native transition
   cannot run safely in this environment, the fix was reverted to keep CI
   stable; the monitor-attached branches are documented as environment
   blockers below.
